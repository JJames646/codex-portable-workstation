# 许可证、商标与商业发布审查

审计时间：2026-07-16
状态：技术初审，不构成法律意见。

## 1. Codex++

- SPDX：`AGPL-3.0-only`。
- 本项目建议直接 Fork 并修改其管理工具、Core 和启动器。
- 修改版分发时需要向接收者提供对应源码和许可证。
- 如果修改版通过网络向用户提供功能，也要关注 AGPL 的网络交互条款。

工程要求：

- 保留版权和许可证。
- Release 包包含 AGPL 文本。
- 提供对应版本源码下载入口。
- 记录全部补丁和构建方法。
- 不把修改版宣传为原作者官方版本。

阻断：

用户已确认可以向接收者提供对应修改源码，因此“Codex++ Fork 作为主客户端”路线可以继续。商业发布仍必须把每个二进制版本与准确源码 commit/tag、构建说明和许可证材料对应起来。

## 2. Sub2API

- LICENSE：LGPL-3.0-or-later。
- README 明确写有上游服务条款风险、免责声明和“无商业授权”声明。

需要分别评估：

1. LGPL 对修改和部署的义务。
2. README 中额外声明的法律效力和作者意图。
3. 实际接入的上游账号/API 服务条款。
4. 是否涉及账户共享、订阅转发或其他被上游禁止的模式。
5. 中国及服务器所在地的经营、支付、数据和网络相关要求。

在得到明确结论前：

- 仅按内部测试环境部署。
- 不以 Sub2API 项目或作者名义销售。
- 不默认启用可能违反上游条款的账号共享模式。
- 优先使用获得合法授权的 API Key 和企业服务。

## 3. unofficial-codex-app-offline

GitHub API 当前未识别清晰的仓库许可证。

仓库会：

- 下载 Microsoft Store 应用载荷。
- 修改 `app.asar`。
- 重新打包 portable ZIP 和安装器。

必须确认：

- 仓库作者代码的使用许可。
- OpenAI/微软应用载荷是否允许重新分发。
- 补丁和打包是否违反应用条款。
- 是否允许商业销售包含该载荷的移动盘。

未确认前：

- 可以用于本地技术验证。
- 不公开发布构建包。
- 不随商品交付载荷。
- 不在 CI 公共 Artifact 中暴露。

## 4. OpenAI Codex 官方仓库

- `openai/codex` 为 Apache-2.0。
- 该许可证覆盖该仓库中的相应源码。
- 不代表 Windows 桌面应用全部资源、图标、名称和商标均可自由再分发。

## 5. 商标与产品命名

风险文案：

- “OpenAI 官方 Codex U盘版”
- “OpenAI 授权便携版”
- “官方 Codex 工作站”

建议：

- 产品 UI 可以说明“兼容 Codex”。
- 在关于页明确“非 OpenAI 官方产品，未获官方背书”。
- “官方中转站”容易产生歧义，建议最终改为“工作站推荐服务”或明确写“本产品官方服务”，不能让用户理解为 OpenAI 官方服务。
- Codex 图标和 OpenAI 标识使用前需核对商标与品牌规则，优先设计自己的产品图标。

## 7. 发布 Gate

### 可以进入内部开发

- 源码审计。
- 本地构建。
- Windows 实机验证。
- 私有 CI Artifact。
- 自有服务器测试。

### 已解除的 Gate

- 用户已接受 Codex++ AGPL 对应源码要求。
- 修改版客户端可以收费分发，但必须向接收者提供对应源码和 AGPL 权利。

### 不可进入公开商业发布

直到以下全部完成：

- 便携桌面载荷再分发许可结论。
- Codex++ 对应源码仓库、版本归档和 Release 关联方式落地。
- Sub2API 商业/条款法律评估。
- 上游模型服务商业授权。
- 商品名称、图标和宣传文案审查。
- 隐私政策、用户协议和数据处理说明。
- 网络、支付、数据和经营相关合规评估。

## 8. 建议的商业安全路线

风险最低的技术组合是：

- 工作站客户端自身源码与 Codex++ 修改版按 AGPL 要求提供。
- 用户自行下载/安装有权使用的 Codex 桌面运行时，或获得明确载荷分发许可后再预装。
- 模型服务只使用合法授权的 API，不使用共享个人订阅作为默认供给。
- Sub2API 仅作为经过法律审查的服务端网关，或替换为自研的合规网关。
